# Sun 01 Nov 2026

**The three that matter:** Jepsen tested ParticleDB, an AI-workload database that
advertised "Full ACID" and a TLA+ proof, and found 96 issues — including a default
transaction mode that loses committed writes. Linux 7.4 deletes binder.c outright and
hands Android IPC to the Rust driver, the first time Rust has replaced C in the kernel
rather than sat beside it. And four Tailscale advisories landed, one of which
Tailscale itself describes as full node takeover.

## Dev + infra

### Jepsen found 96 bugs in a database that claimed a TLA+ proof it never had
Kyle Kingsbury tested ParticleDB 1.1.4 through 1.1.18.11.rc-22 — single node, single
client, no faults. All but ten issues are now fixed, but the default `occ` mode still
loses committed writes and `serializable`, the strongest setting, allows Lost Update.
The home page said "Full ACID. 159K TPS." and "formally proven"; no TLA+ spec existed.
Maker Orkes says 1.1.19-rc.13 closes the rest.
[Jepsen](https://jepsen.io/analyses/particledb-1.1.4)

### Linux 7.4 deletes the C Binder driver and gives Android IPC to Rust
Carlos Llamas's commit is titled `binder: rm -f binder.c` — 11,470 lines out, nine in,
merged to mainline on 24 October. Fifteen years of C that was "incredibly painful to
maintain"; Alice Ryhl's Rust version has feature parity, often beats it on
performance, and has shipped on Android for a while. With no C path left, building
Binder now needs a Rust toolchain.
[commit fd2bc05](https://github.com/torvalds/linux/commit/fd2bc059ed46)

## Homelab

### Four Tailscale advisories, and one of them is full node takeover
TS-2026-016: `tailscale serve` TCP forwards to Unix sockets dialled as root with no
guard, so raw bytes could be fed into the `tailscaled` local API — Tailscale's own
words are "full node takeover". TS-2026-014 let authenticated peers reach root-only
sockets such as Docker's via SSH forwarding. All four, posted 26 October, are fixed in
1.104.4.
[Tailscale](https://tailscale.com/security-bulletins)

## Science + space

### NASA is asking industry whether anyone wants to go fix Hubble
The request for information went out 29 October, responses due 3pm EST on 30 November.
It asks about three things: boosting Hubble to a higher orbit, servicing it to improve
its science, and a controlled re-entry or disposal. The telescope has no propulsion, is
past 35 years old, and is predicted to re-enter in 2033–2034; any mission would fly by
2032.
[NASA](https://science.nasa.gov/missions/hubble/nasa-explores-potential-commercial-servicing-for-hubble-telescope/)
