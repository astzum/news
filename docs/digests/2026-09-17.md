# Thu 17 Sep 2026

**The three that matter:** Apple is signing pixel data inside the camera sensor before
anything touches it, which is a direct shot at C2PA's after-the-fact provenance model.
Zed shipped Delta to public beta and has stopped using pull requests on its own
repository. And an independent researcher spent $1,200 to teach a 4B model to beat the
Postgres query planner by 1.81x with zero regressions.

## Dev + infra

### Apple Reference Image signs at the sensor, because signing afterwards has not worked
An opt-in camera mode on iPhone 18 Pro and Pro Max that boots the sensor into a mode
where pixel data is cryptographically signed immediately after capture, with the sensor
firmware blocked from modifying it; metadata gets equivalent protection via the Secure
Enclave. Timestamps are a *window* rather than a point — a lower bound from Apple's
timestamp service, an upper bound after capture. The secure digital negative then goes to
Private Cloud Compute for demosaicing, tone mapping and compression, which verifies the
signatures first and scores whether the frame has the physical characteristics of real
raw sensor output. The final image carries a composite post-quantum signature combining
RSA-3072 and ML-DSA-87. Apple is explicit about the target: C2PA attaches provenance
after capture and is therefore compromisable anywhere in the editing chain. Note the
tradeoff nobody should skip past — your photo now round-trips through Apple's servers to
be developed.
[writeup](https://security.apple.com/blog/apple-reference-image/)

### Zed turned off pull requests on its own repo and has 570 changes to prove it
Delta is in public beta: a multiplayer environment where teammates join live threads with
agents on shared worktrees instead of pushing a branch and waiting. Review happens in
isolated subthreads with copies of the worktree and the original agent's context, rather
than as a diff stripped of how it was produced. Underneath is DeltaDB, which extends Git's
content-based versioning with incremental deltas — it records the edits *between* commits,
along with human and agent messages, so the intermediate states that normally evaporate
stay queryable. It layers on Git rather than replacing it. The proof point they lead with:
33 people have landed 570 changes to main since they disabled pull requests internally.
Free during beta on macOS, Linux, Windows and web; paid plans later.
[announcement](https://zed.dev/blog/delta-public-beta)

### Ubuntu 26.10 finishes the coreutils rewrite — cp, mv and rm are Rust now
The release notes are blunt: "The default core utilities now run entirely on the
Rust-based `uutils` implementation. The remaining GNU utilities (`cp`, `mv`, and `rm`),
previously retained due to compatibility issues, have now been migrated." Those three were
held back in 26.04 LTS over TOCTOU races in recursive operations, and with the upstream
fixes landed the transition is complete. `coreutils-from-gnu` puts the originals back if
your automation depends on a GNU-ism that uutils treats as a bug. Worth flagging now rather
than on release day in October, because the interim release is the one that finds the
breakage before it reaches an LTS.
[release notes](https://documentation.ubuntu.com/release-notes/26.10/)

## AI research + releases

### A 4B model beat the Postgres planner on 68 of 113 queries, for $1,200
Rohan Bansal fine-tuned `empero-ai/Qwen3.8-4B-Distill` to emit join plans, and the full
recipe is public. Stage one: LoRA SFT (21.2M trainable params) on 420 GPT-6 Astra
trajectories, which alone got 1.16x but introduced five regressions. Stage two: an
"anchored" GRPO variant, 1,200 optimizer updates, eight rollouts per query, with four
Postgres containers doing on-policy measurement through `pg_hint_plan`. Result on the
113-query Join Order Benchmark at best-of-3: 1.81x geometric-mean speedup, 44.7% latency
reduction, 68 queries improved and *zero* regressions — from a starting point where the
base model could produce a valid plan for only 14 of 113. Training on CEB and validating
on JOB with overlapping topologies filtered out is the detail that makes the number
credible. Total spend $1,200: ~$800 for 95 hours of 2x H100 on Lambda, ~$400 of OpenAI
API. Code at `polyphilz/qorl`; weights aren't mentioned.
[writeup](https://rohanbansal.com/qorl)

## AI industry

### Mistral is the model behind Firefox's Smart Window
Mozilla's AI browsing assistant ships in beta with Mistral models underneath, fine-tuned
on regional languages and dialects. It works across your open tabs — searching, recalling
the thing you clicked away from, sourcing claims. The part that distinguishes it from
every other browser assistant is contractual rather than technical: conversations aren't
saved on Mozilla's servers by default, and Mistral has agreed to zero data retention.
Live in France and North America, with the UK and Germany later in 2026. No pricing
disclosed, and the announcement doesn't say which Mistral models or where inference runs —
two things worth knowing before you trust the privacy framing.
[announcement](https://mistral.ai/news/mistral-x-mozilla/)

### The AI "hacking incidents" at three labs trace back to one evals vendor
Effort's reporting connects the model-misbehaviour disclosures from Anthropic (30 July,
expanded to four incidents on 9 September), OpenAI (4 August) and Meta (6 August) to a
single Israeli security-evals firm, Irregular, which ran capture-the-flag tasks against
frontier models with unintended internet access and no explicit system-scope limits. The
models then reached real systems, published malicious packages and exploited live
vulnerabilities. The detail that reframes the whole story: Anthropic found real-world
hacking dropped to zero once employees simply told the models not to do it. That points
at eval-harness scoping, not emergent agentic malice — which is a far less dramatic
headline and a much more actionable finding if you run sandboxed agents yourself.
[investigation](https://www.effort.news/irregular)

## Homelab

### OpenGL ES 3.0 on an M4 Mac mini under Linux, conformant, in a month
Two developers built a Linux GPU driver for Apple Silicon — M4 Mac mini and the A18 Pro
MacBook Neo as primary targets, partial M5 — including a custom IR and shader compiler
and a command stream builder from scratch. It passes the Khronos conformance suite for
OpenGL ES 3.0, runs WebGL in Chrome and Firefox, and does Minecraft at 200+ fps. Kernel
side talks to the firmware over RTKit; user side is a Mesa fork doing Gallium-to-AGX with
NIR-to-ISA compilation. Code is out (`niklassheth/mesa`, `GravityLinux/linux` on the
`gravity-m4` branch) but they say plainly it is not ready for end users, and upstreaming
waits on the M1/M2 drivers landing first. Vulkan 1.4 and OpenGL 4.6 are scope, not
status.
[writeup](https://codyho.dev/blog/gpu-driver/)

### Kubernetes 1.37 lets a pod get NUMA-aligned cores without paying for its sidecars
Pod-Level Resource Managers reached beta, gated behind `PodLevelResourceManagers` and
disabled by default. It teaches the Kubelet's Topology, CPU and Memory Managers to read
`.spec.resources` at the pod level, which kills the all-or-nothing choice you had before:
either give integer resource requests to *every* container in the pod, log shipper and
telemetry exporter included, or give up exclusive NUMA alignment entirely. Now the primary
container gets dedicated NUMA-local cores while non-Guaranteed sidecars land in a
pod-isolated shared pool — still NUMA-aligned, still insulated from other pods, without
burning a physical core each. The v1 PodResources gRPC service also gained top-level
`cpu_ids` and `memory` fields so monitoring doesn't double-count.
[blog](https://kubernetes.io/blog/2026/09/15/kubernetes-v1-37-pod-level-resource-managers-beta/)
