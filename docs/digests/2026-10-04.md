# Sun 04 Oct 2026

**The three that matter:** A university team beat the best Stratego player in history 15–1
using 16 GPUs and a few thousand dollars of training, after DeepMind could not. Aleph Alpha
released Kolibri, a 78B/3B-active bilingual MoE, under Apache 2.0 with weights on Hugging
Face. And Google is donating gVisor to the CNCF, giving up unilateral control of it.

## AI research + releases

### Stratego fell to a training run that cost a few thousand dollars
Ataraxos beat Pim Niemeijer 15–1 with four draws over 20 games, the first superhuman result
in the game. Training was 16 NVIDIA H100s for a week and 163 million self-play games. The
unlock is a separate belief network guessing hidden piece identities, which makes test-time
search tractable. Same recipe yields state-of-the-art Hanabi and dou dizhu.
[paper](https://www.nature.com/articles/s41586-026-11036-y)

### Aleph Alpha's Kolibri is a serious open-weight MoE that is half German
78B total parameters with 3B active, 384 experts routing 6 per token, context to 1M. Trained
on 20T tokens, 4.3T of them German — the bilingual split is the design, not a footnote.
Claimed AIME 2025 at 96.9% English and 87.5% German, GPQA Diamond 84.3%. Apache 2.0, weights
at `Aleph-Alpha/Kolibri-1`.
[announcement](https://aleph-alpha.com/en/blog/kolibri-has-landed-a-sovereign-open-weight-model/)

## Dev + infra

### Zig 0.17.0 makes incremental compilation actually usable on x86_64 Linux
`-fincremental --watch` now works for most projects on that target, and the self-hosted ELF
linker gained full x86_64 plus static and shared library output. The build system splits into
separate configurer and maker executables, and a new Build Server Protocol exposes the
post-configuration build graph to IDEs. `@bitCast` semantics changed and array `**` is gone.
[release notes](https://ziglang.org/download/0.17.0/release-notes.html)

### Google is giving up unilateral control of gVisor, not just donating it
It enters CNCF Sandbox over the coming weeks, aiming at Incubation within months. The
governance change is the real news: non-Google maintainers get merge rights, org-based voting
stops Google overriding them, and Ant Group, Modal and Tines join as long-term maintainers.
The repo leaves the `google` GitHub org.
[post](https://gvisor.dev/blog/2026/10/02/gvisor-cncf/)

### Pi 1.0 is an agent harness that stays small on purpose
Earendil's coding agent hit 1.0 on 1 October under MIT, with deferred tool loading, cache
warming for Anthropic models, mid-conversation system messages and support for non-LLM
models. A companion package, Pi Durable, targets long-running agentic applications. Worth a
look if you want the harness layer legible and hackable rather than a vendor app.
[announcement](https://earendil.com/posts/pi-1-0/)

## AI industry

### DeepSeek shipped its harness as a desktop app, no terminal needed
Public preview worldwide, with macOS arm64 and Windows x64 builds. The harness has been
MIT-licensed on GitHub since August; what is new is the GUI, plugin installs from chat, and a
"Creator mode" that writes plugins for you on request. Tags are still 0.2.x, so treat the
desktop build as a preview.
[preview](https://www.deepseek.com/en/harness/)

### Supabase is buying Turso to make per-agent SQLite databases cheap
Terms undisclosed. Glauber Costa and Pekka Enberg join Supabase's leadership, with Glauber
leading the agentic infrastructure work. Supabase keeps building on Postgres, Turso keeps
working on SQLite, and nothing changes for existing users yet. The stated target: an agent
creating a database as easily as it creates a file.
[announcement](https://supabase.com/blog/supabase-is-acquiring-turso)

## Homelab

### antirez wrote a C inference engine aimed at 64GB Macs and Strix Halo boxes
DwarfStar 4 runs DeepSeek V4 and V4.1 Flash, GLM 5.x and Qwen3.8 Flash Next on Apple Silicon
Metal, CUDA or ROCm. Two ideas earn it the look: asymmetric 2-bit quantisation applied only
to routed experts, and treating the KV cache as a disk citizen so long prefixes resume from
SSD. MIT, with an OpenAI/Anthropic-compatible server.
[project](https://dwarfstar.sh/)
